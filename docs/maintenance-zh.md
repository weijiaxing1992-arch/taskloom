# TaskLoom 社区版部署与维护

## 版本范围与运行方式

本文适用于 0.2.0-rc1 预发布版的 Vue 桌面应用、React 手机工作台、Go API 和 SQLite。社区源码不包含商业门户、原生安装包、私有部署模板、组织快照或任何既有企业数据库。开始前阅读 README.md 和 delivery-deployment.md，所有版本号和依赖以仓库锁文件为准。

源码构建后，README 的 node start.mjs 命令用于本机演示。启动器固定监听 127.0.0.1:8080，固定使用自身目录下 data/community.db、web/ 与独立会话密钥，固定企微 mock 模式。它会覆盖相关环境变量，不能仅给它设置公网环境变量就当作正式部署入口。正式运行应由部署方配置进程管理器直接启动已编译 server。

## 初次账号与数据隔离

空库首次启动预置星河示例企业、8 个部门和 11 位虚构成员。管理员首次账号为 Admin，密码为 123456，必须修改后才能访问业务。未完成改密时服务端拒绝非回环监听，但这不能阻止反向代理转发，因此初始设置不得暴露到公网；远程服务器应通过 SSH 隧道完成设置。示例成员使用独立随机密码，由管理员重设和管理。

不要复制商业系统、其他企业或历史验收环境的数据库来初始化社区版。账号停用、重设密码、组织调整和示例清理应由管理员在明确范围内完成。命令行账号工具先读取 --help 并在独立测试库演练，不要将导出的凭据放进站点目录或 Git。

## 正式环境配置

部署方自行提供 HTTPS 反向代理、进程管理和监控配置。本仓库不附带已经验收的生产部署模板。Go 服务使用回环地址；站点根目录仅指向构建后的 web/，不应暴露源码、data/、备份和环境文件。

至少核对 DEVFLOW_ADDR、DEVFLOW_DB、DEVFLOW_WEB_DIR、DEVFLOW_SESSION_SECRET、DEVFLOW_COOKIE_SECURE、DEVFLOW_SQLITE_SYNCHRONOUS、DEVFLOW_WECOM_MODE 与 DEVFLOW_WECOM_KEY_FILE。生产数据库和密钥使用明确的绝对路径；独立会话密钥至少 32 字节，HTTPS 下启用 Secure Cookie，SQLite 持久性使用 FULL。密钥保存在受权限保护的配置中，不打印在日志或工单。

公开路径以实际部署域名为准；项目空间为 /projects，产品帮助为 /help/guide，API 帮助为 /help/api。示例域名不代表已提供在线服务。反向代理的 Host、TLS、上传大小及超时需要独立验证。

## 一致性备份与恢复

数据库包含需求、评论、附件等业务资料；备份必须与 DEVFLOW_WECOM_KEY_FILE 对应的持久加密密钥配对保存，否则 AI、企微或微信配置可能无法解密。会话签名密钥与加密密钥用途不同，也应按部署方恢复策略保护。

可从 cmd/deployment-preflight 构建工具，以 --db 指定已有数据库，--backup-out 指定不存在的绝对输出路径，使用内置 SQLite 引擎创建一致性备份。该流程不同于离线凭据初始化；不得在备份命令中启用 --provision-copy。工具具体参数以 --help 为准。

不要只复制运行中数据库文件，也不要删除 WAL 或 SHM 来腾空间。备份完成后记录时间、文件大小和校验和，复制到权限独立的备份位置。恢复须在新目录使用快照和匹配密钥，运行完整性检查，并在隔离地址验证登录、权限、附件读取和数据数量。经过实际恢复演练才能评估恢复时间；备份任务存在不等于已经成功备份。

## 升级、静态资源与回滚

每次版本构建使用新的发布目录，保留旧二进制和升级前一致性快照，先在隔离副本上验证数据库迁移。当前服务停止可能中断请求，应安排维护窗口。不要在服务仍运行时覆盖二进制或将旧网页杂项混入新产物。

scripts/retain-web-assets.mjs 可在两个独立、已审查的社区构建目录间保留旧哈希资源，帮助已经打开的页面加载旧模块；它不复制旧 HTML，也不代表完整发布流程。不得以此将商业门户、私有文档或历史构建混入社区发行物。

回滚前核对数据库是否向后兼容。不兼容时应停写、恢复匹配版本快照到新路径，再确认快照之后数据的处理方式。不要在运行中的数据库上覆盖备份或盲目反向执行迁移。

## AI、微信与企业微信服务

AI 配置只读回掩码和配置状态；调用前在界面审核发送内容并确认，真实模型可能收费。PRD、缺陷、测试和升级日志生成均需人工检查，模拟接口测试不能保证真实模型质量。

微信登录需有效的微信开放平台网站应用、正式 HTTPS 域名及正确回调，不能用公众号或小程序凭据替代。回调路径为 /api/auth/wechat/callback；有绑定的应用变更、密钥轮换与登录失败应按界面提示处理。

企业微信机器人与自建应用单独配置。保持 DEVFLOW_WECOM_MODE=mock 时不做真实企微投递；切换 live 前核对服务配置、可信域名、企业可信 IP、成员绑定和真实联调结果，详见 wecom-custom-app.md。个人设置中的邮件通知仅保存偏好，不代表已经提供邮件投递。

## 故障排查与验收记录

先确认运行的是预期版本、数据库路径、密钥文件和监听地址，再查看 /api/health、应用错误和代理错误。内置服务器监控是管理员可读的当前快照，不能替代外部健康探测、备份告警或历史监控。

遇到磁盘不足、数据库锁等待、附件异常或迁移失败时，保留现场并先取得一致性副本。错误报告应使用脱敏复现，不能附上真实数据库、令牌、密码和客户附件。

每次上线记录版本、目标平台、自动化结果、典型角色操作、真实外部服务验证、备份恢复结果与剩余问题。本机构建和测试不构成目标服务器或所有手机浏览器的生产验收。
