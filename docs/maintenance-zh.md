# DevFlow 运维与关键代码说明

## 微信登录配置与运维

管理入口：/organization/wechat-login。微信开放平台需要网站应用的登录能力和 AppID / AppSecret，微信后台授权回调域应与实际 HTTPS 域名一致。完整回调为 https://taskloom.example.com/api/auth/wechat/callback。此配置不同于个人企微通知机器人。

生产反向代理保留 Host，服务设置 DEVFLOW_COOKIE_SECURE=true。绑定和登录必须从该 HTTPS 域名发起，不能从 localhost 开始再跨域完成。服务器需出站访问固定的 api.weixin.qq.com:443；浏览器需访问 open.weixin.qq.com。无需加载第三方登录脚本或放宽全站 iframe 策略。

AppSecret 使用现有持久主密钥进行 AES-GCM 加密，但与 AI/机器人密文采用独立 AAD。备份须配对保存数据库与 DEVFLOW_WECOM_KEY_FILE 所指文件；已有微信密文却缺少密钥时服务拒绝启动，不自动生成替代密钥。不要把回调查询串、Secret 或微信令牌写入日志、监控或工单。

变更配置需要版本匹配，会使未完成扫码失效；已有绑定时禁止直接换 AppID。密钥可留空保留，或关闭登录后明确清除。关闭微信登录不强制退出已登录会话；紧急处置时通过账号管理撤销/停用相关账号。绑定、解绑、成功登录和配置变更写入审计，不包含 OpenID 或密钥明文。

真实验收顺序：配置有效应用 → 密码登录已有成员 → 扫码绑定 → 退出 → 扫码登录 → 验证停用/解绑阻断。无有效 AppID/AppSecret 时仅能验收界面、协议、安全模拟及禁用状态，不得声称真实微信扫码已验证。

## 正式域名与新环境组织初始化

正式门户为 https://taskloom.example.com/portal/，后台为 https://taskloom.example.com/projects，帮助与 API 为 /help/guide 和 /help/api。门户标签统一为“访问后台”。域名的页面后缀保持不变；127.0.0.1 回源、健康检查和本地开发监听不是公网入口，不应改成域名造成循环代理。

新环境专用工具位于 cmd/organization-initialization，完整说明随源码放在 docs/organization-initialization.md。工具只读已审核数据库，复制部门、未删除人员和角色到一个不存在的新数据库路径；不复制业务需求、附件、会话、历史密码、机器人或 AI 密钥。数据包不是日常备份，禁止覆盖已有业务库。

初始管理员凭据通过私有交付渠道提供，公开帮助和门户不包含口令。仅指定管理员激活且首次登录必须改密，其他成员保留组织关系但默认停用。服务首次启动补全缺省配置，随后由管理员核对名单、按需激活并初始化成员凭据。

生产部署使用独立的会话密钥、HTTPS 安全 Cookie 与严格数据库持久性；机器人先使用 mock，另行配置并验收真实发送。参考 deploy/Caddyfile 配置正式代理，部署后验证域名、登录、静态资源和下载链路，不能将配置文件修改等同于完成远端发布。

本说明对应当前仓库实现，用于本地排障和部署交接；不是“已完成生产认证”的声明。端口、数据库和发布目录必须以实际启动参数为准，不能根据浏览器曾访问的地址猜测。以下命令不包含账号密码、会话或 API Key。

```sh
GOCACHE="$PWD/work/gocache" GOPATH="$PWD/work/gopath" \

```

## 数据库：连接、迁移、备份

- `sqlite_store.go` 通过 modernc SQLite DSN 为**每一个连接**设置 WAL、外键、5 秒忙等待及同步策略。不要改成仅在第一个连接执行 PRAGMA。
- `DEVFLOW_SQLITE_SYNCHRONOUS` 只接受 `NORMAL` 或 `FULL`；本地默认 `NORMAL`，生产启动预检要求 `FULL`。更高同步等级不能代替备份与恢复演练。
- 当前部分列表会在持有查询结果时读取关联，连接池不能简单缩成 1。API 并发限制与连接池容量需要一起评估，避免关联查询无连接可用。
- `migration_safety.go` 检查真实结构；`main.go` 以是否已有 `tenants` 表识别首次空库。直接将生产 `DEVFLOW_DB` 指向新路径可能创建演示库，因此应通过拒绝空库的部署启动器启动。
- 不可在运行时手工删除 `-wal` / `-shm`，也不要只复制正在使用的主 `.db` 当作一致性备份。
- 仓库已有 `cmd/deployment-preflight` 的 `--backup-out` 模式，使用与服务端一致的 SQLite 引擎生成并校验新备份，目标必须不存在。先核实源路径，再使用独立新目标。

```sh
/ABSOLUTE/deployment-preflight --db /ABSOLUTE/source.db \
  --backup-out /ABSOLUTE/new-verified-backup.db
```

`deploy/backup-production.sh` 是生产路径的备份脚本模板，备份放在 `/opt/devflow/backups`。仓库提供 `devflow-backup.timer`（服务器时间每日 03:15，另有最多 5 分钟随机延迟），**文件存在不代表定时任务已安装、启用或成功运行**。模板不自动删除旧备份，也不提供异地备份；保留周期、离机复制和恢复演练需要运维另行确认。

数据库中的 Webhook 和 OpenAI Key 是密文，还需备份原始 32 字节主密钥文件：默认路径为 `DEVFLOW_DB` 加 `.wecom-key`，可用 `DEVFLOW_WECOM_KEY_FILE` 指定。密钥要求私有普通文件、权限 0600；库内已有密文而密钥丢失时会拒绝启动，不能生成新密钥掩盖丢失。数据库和密钥的备份应在访问受限的位置分开管理。

## 本地升级与回滚步骤

这些步骤是人工变更检查单，不会自动执行。先取得团队确认，告知短暂切换窗口，并让正在编辑的用户保存草稿；不能为验证新包而强制刷新有未保存内容的页面。

### 升级

1. **锁定精确目标。** 记录监听端口、PID、进程启动命令/工作目录、数据库绝对路径、主密钥路径、旧发布目录和必要环境。可先用 `lsof -nP -iTCP:19082 -sTCP:LISTEN` 核对本地启动脚本默认端口，再对返回的 PID 单独检查；实际端口不同则替换此示例。不要把 `ps e` 等包含全部环境的输出贴到日志，里面可能有密钥。
2. **新包独立准备。** 在新的、非嵌套发布目录准备 server 和 web，不能覆盖仍运行的二进制或旧 `web/index.html`。先执行类型检查/回归，在独立数据库副本验证迁移、登录、权限、附件及基本创建保存。副本应禁用真实企业微信外发，AI 验证使用已有 mock 测试而非拿真实 Key 试调用。
3. **保留旧页面依赖。** 已打开页面会继续懒加载旧内容哈希资源。确认两个目录确实是旧/新 web 后，在切换前运行已有保留脚本；它只向新目录补缺失 assets，遇同名不同内容会拒绝，而不会把旧哈希偷偷指向新代码。

   ```sh
   node scripts/retain-web-assets.mjs /ABSOLUTE/previous/web /ABSOLUTE/next/web
   ```

   此命令会写入新目录，不能对调参数或把数据库/仓库根目录当作 web。两个目录必须存在有效 `index.html` 且不能相同或互相包含。保留静态资源仅解决加载问题，旧页面请求与新后端仍需经过 API 兼容性验证。

4. **形成恢复点。** 使用上一节的一致性备份 helper，目标为从未存在的新文件；同时安全备份匹配的主密钥，限制 0600 权限并记录来源。保留旧发布包和旧签名密钥配置，不把密钥内容写到变更记录。若备份后还有写入，恢复点并不包含这些后续数据；最终切换前应暂停用户操作并形成最后恢复点。
5. **停止精确进程。** 仅对第 1 步核验的 PID 发出 TERM，或停止明确负责它的本地服务单元，再确认对应端口已释放。不要使用 `killall`、模糊 `pkill` 或按所有 Go/Node 进程批量停止。当前 `main.go` 没有信号驱动的 `Server.Shutdown` 排空逻辑，TERM 不能称为优雅停机：先让在途业务请求结束，不能依赖停机过程替用户保存。
6. **保持身份与数据上下文启动。** 显式保留确认过的 `DEVFLOW_DB`、`DEVFLOW_WECOM_KEY_FILE`、`DEVFLOW_SESSION_SECRET`、Cookie 配置，且指向新 `DEVFLOW_WEB_DIR`。使用经过验证的启动入口；不要因路径输错启动空演示库。启动会执行迁移，因此“进程能起”不表示数据库可任意回退。
7. **只读验收后恢复使用。** 核验健康接口、新 HTML 引用的资源及旧哈希 URL、原登录状态、权限目录和数据库关键数量/字段；先读后写。新建只读测试页验证，不抢占用户旧页焦点。确定正常后通知恢复写入，并保留故障观察和回滚记录。

### 回滚

- **优先判断只回应用是否兼容。** 新版数据库结构可能仍兼容旧二进制，也可能新增旧版本不认识的业务约束/数据。只能在独立副本用旧包验证后决定；不要运行未经验证的“降级 SQL”，更不能删除新列、新表或新数据库来强迫旧包启动。
- **先保护故障现场。** 暂停写入，对升级后的数据库另做一致性备份，保存原密钥和新包；记录失败原因与时间。即使准备恢复升级前备份，也不可直接覆盖当前唯一的数据副本。
- **回应用时保留仍被页面使用的资源。** 用独立回滚发布目录准备经验证的旧 server/web，视兼容结果向其中补充用户已打开的新页面所需哈希 assets。新旧 API 不兼容时应在草稿已保存、用户知情后引导重新进入，不用 HTML 兜底冒充缺失 JS。
- **必须恢复数据库时，承认恢复点损失。** 需先确认备份之后新增/修改的数据如何导出、核对或补回，并获得明确确认。将已验证备份恢复到新的独立目录/文件，配置匹配主密钥；停止精确应用进程后才切路径。不要复用原目录中的旧 WAL/SHM，不手工清理活库文件，不覆盖唯一现库。
- **权限和凭据也会回退。** 恢复历史数据库可能恢复旧成员权限、撤销记录或旧会话；必须一并评估是否要执行已批准的会话撤销，不能只看需求条数。签名密钥或凭据重置不是普通回滚的默认步骤。
- 回滚成功后做与升级相同的登录、权限、静态资源及数据验收，并由团队确认恢复使用。备份与保留旧包并不代替完整恢复演练。

## 身份、权限与禁用语义

认证入口是 `auth.go`。签名 HttpOnly Cookie 对应数据库内可撤销的令牌摘要；默认会话期限为 30 天，并非永久会话。生产须配置独立高熵 `DEVFLOW_SESSION_SECRET`，在 HTTPS 反向代理后显式设 `DEVFLOW_COOKIE_SECURE=true`。更换签名密钥会使旧 Cookie 无法认证。

SQLite 暂时故障必须返回基础设施错误，不能伪装成“会话失效”强制用户退出。`authenticate` 的 `last_seen_at` 写入是约 5 分钟一次的辅助记录，失败不应取消已认证会话。

两种禁用不能互换：

- `users.active=0` 或企业成员未激活：不能登录。
- `users.operation_disabled=1`：已激活账户可登录，但不能访问业务接口；仅保留最小会话信息与退出入口，管理员重新启用后可恢复。

`operation_access.go` 是中央业务禁用守卫；代访问身份解析后也要再检查。企业角色、项目角色和用户组授权有不同作用，不可通过隐藏按钮代替服务端检查。人员关联须使用稳定成员 ID，不应按重名显示文本猜测账号。

当前 HTTP 服务仍使用 `main.go` 中固定的 `tenantID` 作为运行企业，尽管数据库表和查询有企业/项目隔离字段；这不是已具备任意企业动态登录路由的 SaaS 部署方案。

当前真实凭据管理路径是：`profile.go` 校验当前密码后的个人改密、`organization_members.go` 经授权管理员设置初始密码，以及 `cmd/admin-credentials` 的精确目标离线变更。公开邮件找回密码及个人微信 OAuth 后端在本次审查版本尚未实现，不能把个人改密称为找回服务，也不能假报邮件已发送。离线凭据工具仅接收安全非交互 stdin，不接受命令行/环境中的密码，且会撤销目标账号会话；使用前仍须明确授权和备份。

## 通知与企业微信

`notification_access.go` 的谓词按每条通知自己的项目检查当前权限，不能仅凭请求头所选项目放行。被移出项目后，其历史通知、未读统计和标记已读目标必须一起不可访问。

`user_wecom.go` 的关键链路是：站内通知写入 → 同事务触发器排队 → 原子领取租约 → 复查账号、项目权限、业务禁用和 Webhook 版本 → 外发 → 保存结果。业务事务回滚不会留下待发送任务。

- 默认 `DEVFLOW_WECOM_MODE=mock`，`mock_sent` 是模拟完成，不表示真实送达。
- 自动化规则产生的 `automation.*` 站内通知不进入个人企业微信投递队列，不能据此承诺所有站内事件都会外发。
- 只有明确配置 `live` 才会调用官方机器人地址；每个收件人还需配置并启用 Webhook。
- `DEVFLOW_PUBLIC_URL` 用于消息中的访问链接，应填写确认过的团队访问入口。
- 请求限定官方 HTTPS 主机，检查 DNS 的实际公网地址，不跟随重定向或系统代理；不要为排障添加任意 URL 或跳过检查。
- 收件人撤权、禁用或配置版本变化会跳过旧任务。当前最多尝试 6 次，失败后留状态供排查，不无限重试。
- 网络成功与本地状态保存之间仍可能发生崩溃，因此不能声称外部通知“恰好一次”；重试存在重复送达可能。
- 只保留脱敏错误码，不应在日志中打印完整机器人 URL、API Key、Cookie 或请求正文。

## AI 服务

`ai_settings.go` 仅允许真实企业管理员配置 Key，代访问不能配置。GET 和审计只展示已配置状态、模型等元信息，不输出 Key。主密钥虽然与 Webhook 共用持久文件，但加密 AAD 使用不同业务域并绑定企业。

`ai_provider.go` 固定调用 OpenAI Responses 官方地址，不接受任意代理 baseURL；当前模型列表在代码中明确列出，不应在运维过程中擅自换模型。用例生成只发送持久化需求标题、正文、验收标准，标题生成的独立接口只发送用户确认的描述；不附带人员、评论、附件或图片。无 Key 时不可伪造成功结果。

输出使用严格结构化格式，但仍须处理拒绝、未完成响应及本地字段/数量/长度校验；不能把模型返回值直接当可信业务记录。相关响应边界参考 [OpenAI Structured Outputs 官方说明](https://developers.openai.com/api/docs/guides/structured-outputs)。生成是预览，人工确认才导入用例；权限、配额、需求版本与配置版本复查不能省略。代码的 `store:false` 是请求配置，不等于自行承诺所有服务端数据保留政策。

## 富文本和附件

`rich_document.go` 只允许约定的 Tiptap JSON 节点与属性；不执行 HTML、不抓取外部图片。图片检查真实 PNG/JPEG/GIF 内容及像素、GIF 帧预算，SVG 不作为内联图片进入渲染链。

待上传数据、附件元信息、文档和审计共用事务；保存后文档必须将临时 base64 换成 `attachmentId`。旧附件必须属于同企业、项目和需求。正文/评论仍引用的附件不能直接删除，避免历史内容断图。旧客户端未改正文时保留富文档；主动改纯文本或传 `descriptionDoc:null` 才切回纯文本。

## 组织导入与常见排障

组织批量初始化使用 [organization-bootstrap.md](organization-bootstrap.md) 所述 `cmd/org-bootstrap`：默认只读预览，`--apply` 才写；先在独立副本演练。按完整邮箱复用账号，现有密码和会话不动；新账号未激活且没有共享初始密码，不发邮件或 Webhook。名单含个人信息，即使没有密钥也应限制文件权限，不应放入静态目录。

排障先确认**当前进程对应的数据库、发布目录和环境**，不要直接改历史 `work/` 副本来“修复”线上：

| 现象 | 优先检查 |
| --- | --- |
| 浏览器打不开 | 监听地址/端口、进程是否存活、反代及防火墙；`GET /api/health` 当前只返回进程健康标记，不完整验证数据库读写 |
| 503 或数据库繁忙 | 磁盘空间、数据库/目录权限、WAL 与连接配置、长事务；不要将错误改成空列表或 401 |
| 无法登录 | 账号激活状态、企业成员资格、凭据及会话签名配置；不要打印密码或共享 Cookie |
| 登录后禁止业务操作 | 核实 `operation_disabled` 和有效权限，不要通过直接开放接口绕过 |
| 密钥缺失无法启动 | 恢复与数据库匹配的原主密钥，核实 0600 权限；不要重新生成替代钥匙 |
| 企业微信未收到 | 先区分 `mock_sent`、`skipped`、`retry`、`failed`；确认 live 模式、收件人权限与配置版本 |
| AI 未生成 | 未配置/未启用、权限或配额、超时/拒绝/内容校验；保留用户草稿，不以假结果替代 |
| 更新后旧页面懒加载失败 | 发布时保留旧内容哈希静态资源，参考 `scripts/retain-web-assets.mjs`；不要强刷尚有未保存草稿的页面 |

重启、迁移、账号变更、名单导入和外发开关均会影响真实用户，应先确认目标、备份及变更窗口，再按批准范围执行。
