# 阿里云服务器与容量建议

交付基线：2026-09-06。面向单企业、最多 10,000 条常规需求。以下是采购与上线建议，不是已采购资源或并发 SLA；地区、价格、实例库存和备案要求须上线前确认。

## 容量假设与结论

推荐先采用单台 ECS + 本地 ESSD + SQLite WAL + HTTPS 反向代理。当前服务不是分布式数据库应用，不要将同一 SQLite 文件放 NAS/NFS 后启动多个写入副本，也不能直接换 RDS 而不改代码。

10,000 条需求不等于 10,000 人同时操作。以约 50 名团队成员、低至中等日常交互负载作为预算起点；实际峰值并发须在目标 ECS 上压测后确认。分页必须启用。大量全文搜索、工作量聚合、AI 调用、完整导出会提高资源消耗。

本机隔离 20,000 条需求、2,000 条缺陷、100 个迭代、20,000 条通知已测试；详情见验收报告。大批量不分页读取仍明显消耗内存，不能把串行基准当成高并发保证。

## 完整资源清单

| 资源 | 建议基线 | 用途 / 约束 |
| --- | --- | --- |
| ECS | 1 台，4 vCPU / 16 GiB，Linux x86_64，Ubuntu 24.04 LTS；通用型如 g9ae 同级 | 运行 Web、Go API、SQLite；具体地域有货实例以控制台为准 |
| 系统盘 | ESSD 80 GiB | 系统、二进制、日志；日志必须轮转 |
| 数据盘 | ESSD 200 GiB，独立挂载 /opt/devflow/data | 数据库含附件 BLOB；WAL 与扩容空间必须预留 |
| 备份空间 | 独立卷或受控备份目录至少 100 GiB 起，随库体积扩容 | 不要只在数据盘保存唯一备份 |
| 私网 | 1 个 VPC、1 个交换机、1 个安全组 | API 仅回环监听，数据库不开放网络端口 |
| 公网 | 1 个公网 IPv4/EIP；初始 5–10 Mbps 或按流量 | 附件下载多时提高带宽；压测后调整 |
| 域名 / DNS | 1 个正式域名 + DNS；HTTPS 443，80 仅跳转 / 证书验证 | 中国内地域域名上线前按要求办理备案；不把 localhost 当公网地址 |
| TLS 反代 | Caddy（交付配置模板） | 自动续证；也可用已维护的 Nginx 但须等价超时 / 请求限制 |
| 异地备份 | 私有 OSS Bucket，版本控制、加密、生命周期 | 上传 SQLite 一致性快照；不直接挂载 OSS 为运行数据库 |
| 云监控 | CloudMonitor 主机 Agent、HTTP 探测、联系人 / 值班组 | 内置运维页面不能替代站外告警 |
| 日志 | journald 轮转；可选 SLS，建议保留 30 天 | 日志脱敏，不采集密码、Token、正文和机器人密钥 |
| 灾备 | ECS 快照 / Cloud Backup；必要时跨地域副本 | 配合应用级备份恢复演练，不承诺自动故障切换 |
| 安全 | 最小权限 RAM、MFA、SSH IP 白名单或堡垒机 | 禁止公网数据库、禁止把 .env / DB / 源码放 Web 根目录 |
| 可选升级 | 8 vCPU / 32 GiB + 更高 IOPS | CPU / 延迟持续超阈值后升级；多节点需先改造数据库与后台任务 |

阿里云通用实例提供 1:4 CPU/内存配置；型号仅为示例。[官方实例说明](https://www.alibabacloud.com/help/en/ecs/user-guide/general-purpose-instance-families)。CPU、网络、磁盘监控可结合 CloudMonitor Agent。[官方监控说明](https://www.alibabacloud.com/help/en/ecs/user-guide/view-the-monitoring-information-of-an-ecs-instance)。

## 附件决定磁盘预算

纯文本需求通常不是主要磁盘占用。示例：10,000 条 × 平均 5 MiB 附件 ≈ 49 GiB；平均 10 MiB ≈ 98 GiB，另加描述、评论、测试记录、索引、WAL 和快照。上述均为规划假设，不是实际测量。

建议日常使用量不超过数据卷 60%–65%；剩余空间要能容纳至少一次完整备份和 WAL 波动。若平均附件达到 10 MiB，应将数据卷及备份空间提高到 400 GiB 或以上，再按实测增长率修正。每天记录库大小、WAL 大小和未来 30 天预测。

OSS 版本控制保留旧版本，也会继续产生存储费用；生命周期要覆盖非当前版本。[OSS 官方说明](https://www.alibabacloud.com/help/en/oss/user-guide/overview-78/)。

## 告警与值班建议

| 指标 | 建议预警 | 严重 / 动作 |
| --- | --- | --- |
| HTTP /api/health | 连续 2 次失败 | 站外 1 分钟探测；联系值班，核查进程和 DB |
| CPU | >70% 持续 10 分钟 | >90% 持续 5 分钟；检查搜索 / 导出 / 异常请求 |
| 内存 | 可用 <20% | <10%；区分主机可用内存与 Go 堆 |
| 数据盘 | 空闲 <30% 或不足 14 天增长量 | <20%；10% 为紧急，不要等数据库写失败 |
| WAL | 连续增长、超正常基线 | 核查长读事务、备份和检查点；不得手动删除 |
| API 延迟 | 目标环境 P95 >1 秒 | >3 秒持续 5 分钟；结合 5xx、锁等待分析 |
| 5xx | >1% / 5 分钟 | >5%；错误日志与请求 ID 定位 |
| 备份 | 最近成功 >24 小时 | >30 小时或恢复校验失败 |
| TLS | 剩余 <30 天 | <7 天；核查自动续证 |
| SQLite | quick_check 非 ok / 外键异常 | 暂停发布，先一致性备份再调查 |

内置监控为只读快照，不提供站外短信、历史时序库或自动扩容。代理后的真实 IP 需配置可信代理范围；不能信任任意客户端传来的 X-Forwarded-For。

## 备份目标与费用边界

建议业务批准目标 RPO 24 小时、RTO 4 小时；若不能接受一天数据损失，改为每小时一致性备份，目标 RPO 1 小时，并重新测量备份耗时。它们是目标，不是已验收 SLA。保留每日 7 份、每周 4 份、每月 6 份；权限隔离后再开启生命周期清理。

ECS 整机快照可补充系统级恢复，但不能替代 SQLite 一致性备份及恢复演练。[Cloud Backup 官方说明](https://www.alibabacloud.com/help/en/cloud-backup/user-guide/ecs-server-backup-overview)。

报价应逐项包含 ECS、系统 / 数据 / 备份盘、公网流量、OSS 所有版本、快照、日志和监控服务；本交付不提供脱离地域及计费方式的固定报价。
