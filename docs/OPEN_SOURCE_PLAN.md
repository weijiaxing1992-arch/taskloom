# TaskLoom · 研织：完整开源计划

版本：0.1.0-rc1；日期：2026-09-09；状态：Apache-2.0 社区预发布，仓库 github.com/weijiaxing1992-arch/taskloom。

## 一、名称与定位

TaskLoom（研织）：AI 辅助的研发协作平台。Loom 寓意将分散的需求、讨论、代码、用例和交付编织为可追溯的工作流。名称暂定，正式发布前检查商标、域名、GitHub/Gitee 同名项目及软件包名称，未承诺名称可注册。

一句话介绍：让需求可理解、协作可追溯、AI 可参与。

目标用户：需要私有部署的小中型研发团队、产品与测试团队、使用 AI 编程助手的交付团队。首版聚焦研发管理，不定位为代码托管、CI 执行平台或通用办公套件。

## 二、开源亮点与功能边界

首版保留：项目空间、需求及子需求、迭代、缺陷、测试用例与执行、我的工作、搜索、通知、组织与权限、附件分类、Markdown/代码编辑、完整需求 JSON/Markdown 导出、API 集成、TAPD PDF 导入、帮助与运维界面。

AI 已实现：标题生成、需求完善的分段预览与选择性追加、测试用例生成与确认导入、用例审查。模型服务由部署方配置和付费；不开启时基础管理功能仍可用。原文、评论及附件属于业务数据，外发前必须披露内容范围并取得用户同意。

尚未实现，不作为首版宣传承诺：自动子需求拆解、需求变更影响分析、跨会话持久化 AI 预览、代码仓库自动读写闭环、AI 额度管理仪表盘。

发行范围：Vue Web + Go API + SQLite；H5 共用网页。历史 Flutter、商业生产 DMG、私有门户发布资源不纳入此首版。后续桌面版以社区 URL 可配置的网页壳单独发行，不能连接原企业生产站。

## 三、品牌与数据独立

社区版独立源码目录、独立数据库、独立编译包，不覆盖商业版服务或迁移生产数据库。UI 使用 TaskLoom／研织；示例企业为星河示例企业，示例项目为星河示例研发、星河示例分析。

示例组织固定生成一次，便于复现、文档和测试：产品研发中心，下属产品部、前端研发组、后端研发组、算法平台组、质量保障部、设计体验部；另有业务运营部，共 8 个部门。预置 11 个虚构成员：Admin、周亦安、程知夏、沈清越、夏景行、陆星河、韩书宁、唐思远、许沐晴、苏予晨、顾南乔。所有邮箱使用 example.com；与真实人员无对应关系。演示需求中的其他称谓也仅为虚构种子内容。

Admin / 123456 仅首次初始化有效。首次登录必须改密，其他业务接口受改密门禁保护；尚未改密时服务端拒绝非回环绑定，远程主机可通过 SSH 隧道初始化。其他演示账号使用独立随机密码且不在日志中输出，由管理员重设后启用。重启不会恢复默认密码。反向代理管理员仍须避免在初始化期间转发公网请求到回环服务。

清理范围：数据库、员工名单、真实域名、密钥、个人草稿、截图、历史发布记录、构建缓存和私有路径。不得为去品牌而删除第三方版权声明、许可证或来源证明。

## 四、许可证与治理

采用 Apache-2.0；完整文本见 LICENSE，归属见 NOTICE。后续贡献和依赖升级必须继续审查权属、许可及供应链风险。

Apache 官方文本：https://www.apache.org/licenses/LICENSE-2.0 。淡化产品品牌不意味着删除法律归属信息。许可证及归属文件已加入；正式稳定版仍需完成发布门禁。

治理：至少两名维护者负责架构和安全；普通修复一人评审，权限、迁移、鉴权、AI 外发及供应链修改两人评审。贡献者通过 DCO 或经审核的贡献协议确认来源。需求讨论使用公开 RFC，发布决策与弃用计划记录在仓库中。

## 五、仓库与工程规范

建议独立仓库 taskloom，main 只接受已验证合并；release/0.x 保留补丁维护。src、cmd、docs、scripts 分别保存前端、服务端、文档、工具。env 与 API 中暂保留 DEVFLOW 兼容标识，后续通过有迁移说明的版本调整，避免机械改名破坏集成。

版本遵循语义化版本，数据库迁移只追加、可恢复并在副本验证。固定 Go、Node、pnpm 和依赖锁文件。源码包应不依赖本机绝对路径；发行前分别在干净 Linux x86_64 和 macOS arm64 构建。

CI 门禁：前端类型与构建、服务端测试、API 权限隔离、迁移重复执行、初始改密与重启保留、XSS/上传大小、跨身份响应隔离、AI 模拟调用、桌面和移动视口布局测试。依赖安全扫描和许可证扫描必须通过或有公开的风险说明，不把历史测试报告当新版本验收。

## 六、发布路线图（建议排期）

1. 第 1 周：独立初始化、去品牌、文档与许可证核对；在两台全新环境完成安装和首次改密。出口：无私密数据、能从源码构建。
2. 第 2 周：打通需求→迭代→缺陷→用例→通知与导出，完善 H5 和权限验收。出口：关键流程无阻断缺陷，备份恢复演练通过。
3. 第 3 周：邀请 3–5 个团队试用 RC，记录安装失败率、首次需求完成时间、核心流程故障，修复问题后发布 0.1.0。
4. 第 4–6 周：按反馈开发 AI 统一入口、待确认问题补答、变更影响分析；通过预览与确认门禁后逐步发布。

排期是计划而非交付承诺。当前候选版只能证明已列明的验证结果，不能宣称生产稳定或通过所有安全扫描。

## 七、社区运营与商业边界

发布材料：中文 README、功能截图（使用虚构数据）、3 分钟上手视频、部署文档、API 示例、迁移示例、路线图、贡献指南与安全政策。GitHub/Gitee 镜像由维护者确认后建立，不自动公开当前代码。

Issue 模板区分缺陷、功能、部署问题；缺陷需提供版本、环境、脱敏复现和预期行为。每周整理高频问题，每月发布维护日志。禁止在公开 Issue 上传数据库、机器人地址、API Key、真实客户需求。

建议核心研发协作与 API 持续开放；收费方向可为托管、部署运维、企业级集成和服务保障。不要通过限制数据导出或移除已开源基本能力制造锁定。

## 八、安全、运维与支持

公开默认密码不用于常态部署。启动脚本生成随机会话密钥并保存在本机受限文件；公网启用 TLS、安全 Cookie 和强密码。AI、微信和机器人默认不配置，通知通道保持 mock，真实外发由部署方确认。备份包含数据库和匹配加密主密钥，必须加密保存并定期恢复演练。

安全报告渠道由维护者发布前填写；未建立私密渠道不得假称有响应承诺。拟定严重漏洞 48 小时确认、7 天给出缓解计划，具体修复时间依影响与复现确定。公布支持版本、数据迁移风险和弃用窗口。

## 九、验收与成功指标

发布阻断项：未确认许可证／版权主体、存在生产秘密或真实人员数据、Admin 改密门禁失效、跨项目越权、不可重复构建、无有效备份恢复流程、核心流程无法完成。

试用指标（先建立基线，非当前成绩）：首次安装成功率、10 分钟内创建首个需求比例、需求到用例的操作耗时、AI 建议采用率、生成失败率、每周活跃团队、问题首次响应时间。不得用虚假 star 数、用户数或未经压测的容量指标宣传。
