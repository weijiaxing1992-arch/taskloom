# AI 迭代升级日志

## 使用入口

企业管理员先进入“AI 服务配置”，配置可用的服务地址、API 密钥和模型，启用 AI 服务，再按需开启“完成迭代后自动生成升级日志”。该开关默认关闭；开启时页面会明确提示发送范围、目标地址和可能产生的模型费用。

迭代进入“已完成”后，迭代详情顶部显示“升级日志”入口。系统会在后台生成草稿，不阻塞迭代完成，也不会自动发布到门户、飞书或其他外部平台。具有迭代管理权限的成员还可在该入口手动生成或重新生成。

## 固定内容规范

每份升级日志固定包含版本名称和迭代完成时间，并按以下顺序展示七个章节：

1. 大模型类型
2. 智能体类型
3. AI呼叫类型
4. CRM/短信/账单
5. 管理端/代理端
6. API接口
7. 其他

系统只纳入当前迭代中状态为完成的需求，缺陷、Bug 和 Defect 不进入生成来源。每个来源需求恰好对应一条升级内容，不合并、不遗漏、不重复；同一分类内按需求编号排序。分类由服务端固定规则确定，AI 只改写功能标题和说明，因此更换模型或拆分批次不会改变章节顺序。

生成内容只能使用已保存的需求标题、正文和验收标准，不把计划、待办、取消内容或问题描述虚构成已上线能力。来源不足时会保留该需求，并提示人工核实具体交付变化。

## 配图与发布检查

AI 只能看到图片候选的编号和文件名，图片文件本身不会发送给模型。生成后请点击“编辑日志”，从每条需求自己的真实图片附件中选择 0–8 张截图，并填写准确图注；不能引用其他需求的图片，也不会生成虚构配图。

“发布检查”会显示需求覆盖数和待补图数量：

- 文案与配图均已保存时，可下载发布图文包。
- 存在无图条目时，仍可下载审核图文包，但应先补图再对外发布。
- 来源需求、附件或 AI 配置变化后，旧草稿会标记为过期，必须重新生成，不能静默覆盖。

图文包为 ZIP，包含 `upgrade-notes.md`、`upgrade-notes.json`、`README.md` 和本地 `images/` 目录。Markdown 中的图片会改写为离线路径，解压后无需登录即可审阅。导出动作只下载文件，不代表已经发布。

## 权限、失败与重试

项目成员可查看本项目已有草稿；企业管理员、项目管理员、产品及前后端负责人可生成和编辑。代访问期间禁止生成和编辑。手动生成会复核当前会话，自动任务也会在调用模型前重新检查发起人、项目、角色、迭代、来源指纹和 AI 配置版本。

任务使用持久化队列并最多自动重试三次。网络或服务商暂时失败不会留下半份草稿；进程重启后可以继续处理。连续失败、配置变化或来源变化会显示明确状态，管理员修复问题后可从迭代入口手动重试。

## 团队洞察与版本追溯

“团队洞察 → 升级日志”展示的是 `release_note_jobs` 与 `release_note_drafts` 中已经保存的版本快照，而不是用当前需求重新生成的临时页面。列表按最近保存时间展示版本名称、时间、需求数量和配图数量；详情固定保留七类章节、每项需求的标题、正文、验收标准、已选择的真实截图和图注。历史迭代后来被改名、需求后来被编辑，也不会静默改写这份已保存的版本记录。

查看团队洞察需要同时具备当前项目成员身份和企业 `reports.view` 权限。内部页面读取 `GET /api/reports/release-notes` 或 `GET /api/reports/release-notes/{sprintId}`；这两个读取接口只接受当前项目范围，不读取 AI 服务设置、API 密钥或任务会话。详情中的截图预览仍通过站内需求附件权限读取，无法用列表 ID 换取其他项目的图片。

自动化系统可为项目绑定 Bearer 凭据增加 `release-notes:read`，再通过对外 `GET /api/open/v1/release-notes` 和 `GET /api/open/v1/release-notes/{sprintId}` 读取相同快照。对外响应保留需求正文、验收和截图校验元数据，但不返回内部附件 URL 或二进制文件；调用时仍会复核当前项目成员与 `reports.view`。缺陷不进入列表、详情、Markdown 或 JSON 导出。

## 内部接口摘要

以下接口属于站点内部会话 API，不是开放 API 或 MCP 的兼容承诺：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/sprints/{id}/release-notes` | 读取任务、草稿、分类、来源和图片候选状态。 |
| POST | `/api/sprints/{id}/release-notes` | 显式确认后排队生成；重新生成必须确认替换草稿。 |
| PATCH | `/api/sprints/{id}/release-notes` | 按版本保存人工复核后的文案、分类、图片和图注。 |
| GET | `/api/sprints/{id}/release-notes/bundle?expectedRevision={revision}` | 下载当前版本的离线图文包。 |
| GET | `/api/reports/release-notes` | 团队洞察中的项目范围历史快照列表；需要项目成员和 `reports.view`。 |
| GET | `/api/reports/release-notes/{sprintId}` | 团队洞察中的一份完整版本快照详情；需要项目成员和 `reports.view`。 |

写入使用版本字段防止多人覆盖；遇到 409 时先刷新并核对最新来源，不应重复提交旧草稿。AI 密钥不会出现在响应、草稿、审计记录或导出文件中。
