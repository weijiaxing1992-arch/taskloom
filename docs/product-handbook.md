# TaskLoom 产品使用手册

## 手机 H5：四个常用入口

在手机窄屏中，“我的工作、全局搜索、通知中心、项目空间”底部提供快捷切换，通知入口同步显示未读数。其他模块通过左上角主导航进入；底部栏不覆盖列表末尾。四个入口不重复显示顶部搜索和项目模块导航，优先把屏幕留给工作内容。

- 我的工作：先点工作分类或进行中迭代；点击“筛选”展开项目、类型、状态和排序。收起只隐藏控件，不会清除条件，按钮上的数量表示仍在生效的高级筛选；“重置筛选”清除这些高级条件，保留关键词与当前工作分类。
- 全局搜索：支持中文连续输入，输入法确认前不请求半成品词；按键盘搜索键立即检索。进入页面不自动弹键盘，类型与项目可直接筛选，导出入口与标题同行。
- 通知中心：消息分类横向滑动，未读筛选常驻，事件与项目放在“筛选”内。消息正文仍完整显示，点击通知进入有权限的详情；“设为已读”不等于完成业务交接。
- 项目空间：卡片集中展示项目名称、需求、缺陷、迭代、用例和成员数量；管理操作仍按原有权限显示，下方“最近内容”快速回到工作项。

管理员在任意企业管理页面右上方都可点击“微信登录配置”。若没有此入口，请确认当前是企业管理员本人，非普通成员或代访问状态。

## 微信绑定与扫码登录

微信登录与企微机器人通知独立：微信登录验证个人身份，企微通知向机器人推送消息，二者不能共用应用凭据。

管理员进入 [微信登录配置](/organization/wechat-login)，填写微信开放平台网站应用的 AppID、AppSecret 与正式 HTTPS 域名，核对完整回调地址后保存并启用。AppSecret 加密保存在服务器，读取配置不会回显；修改配置会使尚未完成的扫码失效。当前没有真实应用凭据时，不会展示假二维码或声称已经可用。

成员首次使用先通过邮箱密码登录，进入 [个人设置](/profile?tab=wechat) → 微信绑定，确认当前密码后点击“绑定微信（扫码）”。系统打开微信官方二维码页面，用手机微信扫描并确认，成功后自动返回个人设置。不会按昵称自动创建、匹配或合并组织成员，同一个应用中的微信只能绑定一个人员账号。

绑定后可以退出，在登录页点击“微信扫码登录”，扫码确认后返回后台。二维码有效窗口为 5 分钟；本产品的授权状态一次使用即失效，刷新、过期、配置变更或服务失败后请重新发起。为防止跨站登录攻击，必须在管理员配置的 HTTPS 域名发起；不能从 localhost 发起后回到另一个域名。

更换微信时先在个人设置确认密码并解绑，再重新绑定。解绑会撤销其他浏览器的会话，当前经过密码确认的会话保留。账号停用后不能扫码登录；首次改密仍需完成后才能进入业务页面。请保留可用密码，避免微信不可用或手机丢失时无法登录。

手机 H5 同样可以进入官方扫码流程，但这不是微信内网页静默授权；如果只有一部手机、不方便扫描本机屏幕上的二维码，请使用邮箱密码登录。原生 Mac 客户端暂未接入本轮 Web 扫码流程。

遇到失败时，先查看登录页或绑定页提示。管理员核对网站应用类型、登录权限、AppID、AppSecret、授权回调域及 HTTPS 服务；不要填写公众号或小程序的凭据。扫码真实联调需要有效的微信开放平台应用，不可用模拟测试替代。

## 手机 H5 使用与布局

手机浏览器使用与桌面相同的 HTTPS 后台地址，无需安装 Mac 应用。Web 与 Mac 原生客户端是独立版本，当前 Mac 下载仍是开发测试包，不能据此推断全部 Web 功能都已在 Mac 交付。

1. 顶部项目导航可以左右滑动；窄屏下搜索框会另行排列，避免挤压操作。
2. 需求、缺陷、迭代和管理页的宽表在表格区域左右滑动。可以减少可见列；不会为了适应屏幕而静默丢弃业务字段。
3. 详情抽屉在手机上全屏显示。点击存在的外部遮罩关闭当前最上层弹窗；没有露出的遮罩时使用关闭按钮。未保存修改和提交中的保护仍然生效。
4. 帮助中心顶部文档标签可左右滑动；点击“查看章节目录”展开目录，再选择章节。搜索可跨产品手册、API、AI 接入和运维文档查找。
5. 代码块与长表可以在自身区域横向滚动。正文可粘贴 Markdown，评论可粘贴代码和截图；导出 JSON / Markdown 时保留相应结构。
6. 页面字号、触控高度和底部安全区域统一适配。若系统字体放大后仍有遮挡，请反馈页面地址、屏幕宽度、浏览器及截图，不要用缩小整页替代问题修复。

## 与我相关：筛选范围与选中状态

迭代列表的“与我相关”选中后显示主题色底、白色文字和勾选标记，再次点击恢复普通状态。这是筛选状态提示，不改变任务权重、权限或工作量计算。

人员字段、工程师角色字段、创建、评论参与及 @ 提及等关联会纳入相关范围，实际结果始终受项目访问权限约束。它可以与搜索、状态及迭代范围叠加；结果为空时先检查组合条件，不代表数据已删除。

## 初始化账号与安全交付

新环境使用管理员私下交付的初始化包。包中包含审核后的现有部门树、人员、项目角色及用户组关系，不包含测试需求、评论附件、历史密码、会话、API 令牌或机器人密钥。

初始管理员凭据不在门户、帮助中心或公开源码中发布。首次登录后必须更换初始密码；其他成员保持停用，由管理员激活并通过账号初始化流程分发凭据。初始化包只能安装到全新数据库路径，不能覆盖已有业务库。账号停用不等于从组织结构中删除。

## 遮罩关闭与我的工作迭代筛选

点击弹窗、详情抽屉外的遮罩，会调用与关闭按钮相同的关闭操作；点击内容区不会误关。多层弹窗只关闭最上层，不穿透关闭底层。未保存修改仍走原有草稿或确认流程，正在提交的操作保留关闭保护。

“我的工作”新增进行中迭代快捷按钮，点击选中迭代，再次点击同一按钮取消筛选；也可用“全部迭代”下拉选择规划中或历史迭代。跨项目时显示项目名称，选择使用迭代编号，不合并跨项目同名迭代。迭代与关键词、工作类型、状态、项目和工作分类组合生效，切换项目会清除旧迭代条件。

筛选保留“与我相关”范围；“我的收藏”也支持相同迭代筛选。需求和缺陷按所属迭代，测试执行按计划迭代，测试用例按关联需求的迭代归入；未纳入迭代的项目不会混入所选迭代。


## 附件资产分类与代码预览

需求详情的「附件资产」统一汇集正文和需求评论中的上传文件，可按缺陷、接口、设计稿、代码及其他筛选；Figma 归入设计稿。上传前选择分类，也可上传后直接调整。分类以附件记录为准，修改会同步当前页面的评论图标并记录审计。

每种分类使用不同图形，代码文件另带 Vue、PHP、Go、C++、JS、TS 等语言徽标。业务分类与语言独立，接口分类也可以包含 Go 文件。自动分类优先依据文件名；名称不明确的文本文件会用有限内容前缀识别明确的代码语言，不自动创建缺陷。

代码预览保留原文、中文、缩进和换行，支持 UTF-8 及带 BOM 的 UTF-16。大文件分段阅读，“复制完整代码”与原文件下载不会截断；预览只做语法高亮，不执行代码或 HTML。未知编码、压缩包、二进制文件请下载查看。单文件上限 10 MiB，富文本单次待保存文件总计 20 MiB。JSON/Markdown 导出的附件索引同时带上分类、语言和需授权的下载地址。

## 智能粘贴与 AI 导出

需求编辑器默认开启“智能粘贴”：明确代码自动识别语言，Markdown 自动转换为标题、列表、引用、表格和代码块等结构；支持一到六级标题。代码块内部粘贴仍保留原文，识别有歧义可关闭智能粘贴或手选语言。备注也支持粘贴代码、插入代码块和 Markdown/代码预览。

JSON 导出新增 aiContext 阅读指引、结构化 Markdown 正文与 codeBlocks 原始代码。Markdown 导出新增按需求组织的 AI 阅读稿，并保留全部原始数据分组，覆盖需求树、所有公开评论、测试用例、缺陷等资料。附件提供索引和下载入口，不内嵌二进制；未保存草稿、密钥和无权限数据不导出。完整范围见文件中的 completeness。

## 与我相关与代码阅读

需求、缺陷和迭代工作项的“与我相关”按钮覆盖所有人员字段、工程师角色、明确的 @ 提及、创建和评论参与，并可组合其他筛选。“我的工作”使用同一判定，已读不影响关联；项目权限仍然生效。

需求正文与评论可插入代码块，支持自动识别或手动选择 Vue、PHP、Go、C++ 等语言，提供语法高亮、换行与原始代码复制。需求详情点击“编辑正文”后编辑代码。缺陷编辑和评论输入区提供“插入代码块”“代码预览”；发布后保留围栏格式并高亮展示，不执行代码。本次不新增已发布评论的修改权限。

迭代关联筛选不改变概览总数；旧的个人列配置不变。

本手册面向产品、研发、测试和管理人员，按当前产品实际流程编写。页面名称以中文界面为准；切换语言不会翻译用户填写的需求、评论和项目名称。本文示例均为虚构，不包含可直接使用的账号或密码。

先确认当前账号和项目，再进行业务操作。按钮是否出现、可选人员和状态范围，都受到当前权限、项目状态和账号状态约束。看到“保存成功”“已导入”等明确结果后，才把操作视为完成。

## 01 首次使用与角色范围

### TAPD PDF 迁移

需求池右上角新增“TAPD 迁移”，供项目管理员和企业管理员使用。上传 TAPD 打印 PDF 后，先核对字段映射、可编辑正文和逐页图像，再勾选确认并创建。支持最多 30 页、10 MiB 的单条需求 PDF。

同名人员、不存在的分类或迭代需要人工选择。没有等义目标的字段可“仅保留来源字段”，原值仍完整进入备注和附件。未映射时采用项目初始状态、未分类、待规划、P2；可用“补充目标字段”填写其他必填信息。原始 PDF、完整字段对照 JSON、页面图像会一同保存，重复文件不重复创建。

来源创建人及时间只留档，不替代本系统审计信息；UI 奖励不等于 UI 难度，组长不等于工程师，不会自动混用。PDF 中没有的评论、子需求、用例及外部附件无法凭空恢复。扫描 PDF 暂不提供 OCR。完整字段说明见代码包 `docs/tapd-migration.md`。

入口：[项目空间](/projects)、右上角账号菜单、[企业管理](/organization)。

### 建议的上手步骤

1. 使用管理员提供的登录邮箱和凭据登录，按要求完成首次改密。
2. 进入有权访问的项目，确认顶部显示的项目名称。
3. 产品先整理需求和验收标准，研发补充人员、权重及排期，测试维护用例并组织执行。
4. 在通知中心查看分配和提及消息，在“我的工作”聚合个人待办。

### 权限分为两个层次

| 层次 | 作用 | 常见情况 |
| --- | --- | --- |
| 企业角色与用户组权限 | 管理成员、部门、加入申请和公司级统计 | 普通成员可被单独授予部分管理能力，不必成为企业管理员 |
| 项目角色 | 决定当前项目的业务写入及状态流转 | 产品、前后端、算法、UI、组长、测试、项目管理员、只读成员 |
| 工作项人员绑定 | 表示某条需求的负责人、职能参与者等 | 被选为负责人不等于获得企业管理权限 |

注意与常见问题：只读成员可以查看获授权的业务内容，但不能据此创建、编辑或评审。项目管理员不自动拥有全公司的人员管理和工作量报表权限。同一人在不同项目可以拥有不同角色；遇到按钮缺失，应先检查项目与账号，再请管理员核对授权。

## 02 登录、首次改密与退出

入口：登录页；登录后进入[个人设置](/profile)的“账号安全”。

### 操作步骤

1. 输入登录邮箱和密码。登录页可记住上次使用的邮箱；点击邮箱标签可快速填入，旁边的清除按钮只清除邮箱记忆。
2. 若账号被要求首次改密，先设置新密码并再次确认；完成前不能进入正常业务操作。
3. 日常改密时填写当前密码、新密码和确认密码。新密码至少 8 个字符，须包含字母和数字，并遵守页面长度限制。
4. 公用设备使用完毕后主动退出。默认登录会话有 30 天有效期，并非永久登录；退出、密码变更或管理员撤销会话都可能要求重新登录。

注意与常见问题：不提供公开通用密码；管理员设置的临时密码应通过受控方式交付。未激活或已停用账号不能正常登录；“业务操作已禁用”则可能允许登录，但只能看到禁用提示。忘记密码时联系管理员，不要反复尝试或向评论、截图中填写密码。网络故障提示“暂未确认登录已失效”时，优先使用“重新连接”，不必反复登录。

## 03 工作台导航与我的工作

入口：侧栏工作台；[我的工作](/my-work)。

### 操作步骤

1. 通过顶部项目选择器切换项目。桌面侧栏可以展开或收为图标模式，窄屏使用菜单打开导航。
2. 在“我的工作”选择“与我相关”，或切换到收藏视图。需求任意启用且未删除的人员字段、负责人/处理人、职能角色中包含当前账号，或正文、备注、已保存评论中明确 @ 当前账号，都会纳入。多种关系同时命中仍只显示一次；通知已读不影响归属。普通文本中的同名姓名不是明确提及，移除正文/备注提及后不再凭旧通知纳入。
3. 按项目、工作项类型、待办/进行中/临近到期/逾期等分类查找，再按优先级、更新时间或截止时间排序。
4. 点击工作项进入详情。跨项目打开时会切换到该工作项所属项目，并重新校验访问权。

注意与常见问题：“我的工作”汇总需求、缺陷、迭代、测试用例和执行任务，不只是自己创建的内容。收藏需求可以由其他人负责，但仍须有访问权；收藏不是授权，也不会把它自动分配给自己。找不到工作项时，清除筛选并核对负责人绑定及项目权限。

## 04 项目空间、归档与恢复

入口：[项目空间](/projects)，或企业概览的已归档项目入口。

### 操作步骤

1. 使用名称、代号或说明搜索项目，点击项目进入需求池；常用项目可以收藏。
2. 有管理权限时创建项目，填写名称、代号、说明及页面提供的负责人等信息。后续业务数据归属于该项目。
3. 项目停止日常协作时使用“归档”。归档后不再作为活动项目供常规切换和新增业务操作。
4. 企业管理员可进入“已归档”目录恢复项目；恢复保留成员和既有工作项。
5. 删除仅对已归档项目开放，需要明确确认并准确输入项目代号。

### 选择项目成员

1. 企业管理员或获授“管理成员”权限的成员可在活动项目卡片打开“管理成员”；创建项目后也可直接进入成员选择。
2. 搜索成员，逐个勾选或全选当前筛选结果。清除搜索不会清空已选人员，提交前核对新增和移除名单。
3. 保存时只提交本次新增/移除差异。新增成员默认只读，已有成员保留原角色；后续可在成员配置中调整必要的项目角色。
4. 加入项目不等于激活账号。未激活成员可以预先加入，但需管理员完成激活及凭据配置后才能登录。

注意：不能从项目移除自己或企业管理员，委派管理员也不能借此移除高权限成员。一次变更最多涉及 200 人；校验失败则整体不保存。归档和已删除项目不提供成员变更入口。

注意与常见问题：归档不等于删除；删除项目也不是物理清除需求和附件，而是让该项目退出可用业务范围。界面没有删除后的普通恢复入口，误删应由管理员和运维核查审计及备份。项目代号不能因删除而随意复用。收藏和最近访问只帮助导航，不能扩大权限。

## 05 需求池、分类与列表视图

入口：[需求池](/requirements)。

### 操作步骤

1. 从左侧选择分类，或查看全部/未分类需求。
2. 输入关键词，叠加迭代、状态、人员及高级条件筛选；多选状态表示“其中任一状态”，不同筛选条件共同限制结果。
3. 在列表与看板之间切换，使用排序控制查看顺序。看板中较长摘要可展开阅读。
4. 打开列配置，搜索并选择要显示的字段，调整列顺序后保存。需求编号和标题等必要信息会保持可用。
5. 有管理权限时创建、重命名或调整分类顺序。删除分类时，分类中的需求移至“未分类”，不会一并删除。

注意与常见问题：表头全选通常是当前页选择，不能将其误认为全部筛选结果。列表列配置只影响自己的当前项目视图，不修改需求字段本身。分类或配置被他人修改后可能需要刷新重试；系统不会用旧排序覆盖新结构。结果为空时先清除所有筛选，而不是重新创建同一需求。

## 06 保存个人视图与共享视图

入口：[需求池](/requirements)的视图管理和列配置入口。

### 操作步骤

1. 先调整筛选、排序、显示列和列表/看板模式，确认当前结果符合目标。
2. 保存为个人视图，填写容易识别的名称，例如“本周待评审”。
3. 需要团队共用时，按页面提供的权限创建或维护项目共享视图。
4. 应用视图后检查条件和结果；维护共享视图前确认不会影响同事常用入口。

注意与常见问题：个人视图与共享视图保存在服务器，不等于只在当前浏览器记住一个筛选。共享视图受项目权限和版本检查约束。若其中字段被删除、禁用或引用已失效，系统会提示视图不可用，不会悄悄忽略条件而扩大查询范围；请修复视图配置或重新选择有效字段。

## 07 创建与正式编辑需求

新建页面默认采用快速收录布局，先填写标题和描述，可直接调整优先级。“展开更多信息”显示类型、验收标准、职能评估、人员、计划与扩展字段；收起不会丢失已有输入。项目配置的必填字段仍需填写，校验失败会展开对应区域。同名提示仅用于核对已载入的需求目录，不是唯一性保证。

入口：[创建需求](/requirements/new)，或需求详情中的编辑入口。

### 操作步骤

1. 填写标题，写清业务背景、范围、描述和验收标准，按项目规则选择类型、分类及优先级。
2. 设置负责人、处理人、迭代、计划日期、职能人员和工作权重，补充项目要求的自定义字段。
3. 点击“创建需求”或“保存修改”。连续录入可使用“提交并继续创建”。
4. 标题为空且功能可用时，可明确确认发送正文文字给 AI 生成标题；检查并采纳后，仍需再次正式保存需求。

注意与常见问题：新需求的初始状态由当前项目工作流决定，不由恢复的草稿强行指定。生成标题只辅助命名，不会自动提交需求；正文含敏感资料时应先脱敏或不使用外部 AI。日期无效、必填字段缺失、人员失效或并发版本变化会阻止保存；请修正提示，勿反复点击制造重复工作项。

## 08 私有草稿与恢复

入口：带“草稿箱”的需求和缺陷编辑器。

### 操作步骤

1. 开始编辑后留意草稿状态。编辑内容会每 30 秒尝试自动保存，也可主动点击“保存草稿”。
2. 确认提示是“已保存到本机”“等待同步”还是“已保存到本机和私有草稿箱”，不要把这几种状态混为一谈。
3. 打开草稿箱，选择对应的新建草稿或编辑对象，点击“恢复到编辑器”。
4. 核对恢复内容与当前正式版本，再点击正式保存。正式接口成功后才清理对应草稿；清理失败不代表需求保存失败。
5. 需要留存时，下载可查看的 HTML 或完整 JSON；确定不用的草稿需二次确认删除。

注意与常见问题：草稿按企业、账号、项目隔离，不是团队共享工作项。自动保存写入本机存储和私有草稿服务，不会创建或修改正式需求/缺陷。两个页面发生草稿冲突时会保留副本，需人工比较。未同步草稿仅在本机；清除站点数据前务必导出。导出文件可能包含未上传图片、附件和业务文字，应按业务资料保管。私有草稿不能替代完整数据库备份。

## 09 需求详情、人员、评估与权重

入口：点击需求编号或标题打开详情抽屉。

### 操作步骤

1. 阅读正文、验收条件和右侧属性；需要更大空间时拖动抽屉边缘调整宽度，或进入完整编辑页。
2. 正文编辑后点击“保存正文”；评估、补充信息等区域修改后点击对应保存按钮。
3. 多选产品负责人和处理人，检查顺序与主负责人后分别保存。使用成员选择器搜索姓名或按部门筛选。
4. 在职能区域绑定实际参与人员，并填写前端、后端、算法、UI、产品等权重；标签、检查项和补充字段按项目约定维护。
5. 离开时遇到未保存提示，应选择保存、继续编辑或明确放弃，不要把切换面板当成保存。

注意与常见问题：详情中有立即提交的属性，也有必须点击保存的编辑区域，应以区域按钮和“尚未保存”提示为准。权重是团队用于规划的相对工作量，不等于小时，也不是个人绩效。人员候选还受部门、角色和有效项目成员条件限制；历史人员名称可能保留，但不能据此再次选用已失效成员。

### 导出单条需求的完整资料

1. 先保存需要留存的正文、属性及评论，再在需求详情或完整编辑页打开“导出需求”。导出只读取已保存版本，不包含浏览器未保存的修改或私有草稿。
2. 选择“导出 PDF”用于查看和打印，或选择“导出完整 JSON”“导出完整 Markdown”用于程序处理、文本协作和模型阅读。原有 PDF 下载仍然保留；列表 CSV 则只提供清单，不等同于完整资料导出。
3. 等待生成完成后下载，需要停止时点击“取消导出”。检查文件中的来源项目、根需求、生成时间和完整性说明，再决定分享范围。

JSON 和 Markdown 使用相同的只读数据快照：根需求及全部递归子需求的业务字段、验收标准、人员、标签、自定义字段、检查项、备注、活动、设计资料，以及全部公开评论和回复。测试资料包括直接关联及通过测试设计点挂接的用例、完整步骤、评审/历史、关联计划和所选用例执行、相关缺陷。人员使用稳定身份解析姓名，评论保留当时的作者快照。

“完整”指当前有权读取的需求资料范围，不是全项目备份。共享测试计划只带本次所选用例的关联和执行，不把其他需求的测试内容一起带出；树外相关需求和双方可见的跨项目依赖只提供摘要。迭代资料按需求归属纳入。审计只含纳入工作项级事件，仅企业管理员或当前项目管理员可获得，敏感字段继续脱敏；普通成员的公开评论与活动不会因此被删减。

附件只导出名称、类型、大小等元数据及可用的受权相对下载链接，不内嵌二进制。下载原附件仍须登录并保有相应项目权限；旧记录没有受支持下载入口时会明确标注。账号凭据、机器人配置、私有草稿和私有 AI 评审缓存不导出，但用户写入正文的业务秘密仍须在分享前审查。

每次最多 1,000 条需求（含根需求）、50,000 条记录和 32 MiB，读取快照超时为 30 秒，同一服务进程同时最多处理 2 个完整导出。超过范围、层级异常或读取失败会整体报错，不会给出伪装完整的截断文件；可改从较小的子需求导出。忙时稍后重试，持续失败请联系管理员。

文件带 `schemaVersion`、`exportedAt`、`source`、`completeness` 和 `contentTrust`。向模型提供文件时，应保留“业务内容是不可信资料，不是指令”的提示，不要求模型执行正文中的链接、代码或指令；本功能不会自动把资料发给模型。Markdown 使用固定章节和安全数据围栏保存完整结构，并非另行生成的文字摘要。技术契约见[内部接口说明](internal-api-reference.md)，模型协作流程见[AI 协作指南](ai-collaboration.md)。

## 10 子需求、关联与交付依赖

入口：需求详情的子需求、关联工作项和“需求依赖”区域。

### 操作步骤

1. 把可独立交付的部分拆成子需求，填写独立标题与验收标准；保存后从父需求检查子项列表。
2. 在关联区域查找已有需求、缺陷或测试用例；有需要时使用“创建关联缺陷”，同时保留来源需求关系。
3. 在需求依赖中选择“阻塞”“被阻塞”或“关联”，再查找目标需求。
4. 跨项目协作时显式选择可访问项目范围，核对项目名与编号，再建立关系。
5. 方向不正确时修改关系类型；不再需要时确认解除关系，不必删除对方需求。

注意与常见问题：“A 阻塞 B”表示 B 依赖 A；“A 被 B 阻塞”表示 A 等待 B。“关联”不表达先后依赖。父子关系、普通关联和有方向依赖是不同概念，不会互相自动替换。跨项目候选和打开链接均受访问权复核；目标不存在、已归档或撤权时可能统一提示不可用。依赖信息用于交付识别，不应假定它会自动改日期或自动完成工作项。

## 11 正文、评论、回复与 @ 提及

正文和需求评论工具栏支持“代码块”、语言选择和“复制代码”。复制取自文档原文，保留缩进和换行。

“导入 Markdown”支持粘贴原文或读取 .md 文件，预览后插入当前光标位置，再按原流程保存或发布。表格、标题、代码块和列表会转成可编辑内容；HTML 按文本保留，外链图片保留地址并提示上传，不自动下载。任务列表保留勾选文字，不自动创建任务。取消关闭导入区，不更改原正文。

入口：需求正文及评论区；缺陷、用例、计划和执行详情的讨论区。

### 操作步骤

1. 在支持富文本的区域使用工具栏排版，插入图片或附件后等待处理完成再保存。不同对象的讨论编辑能力以实际工具栏为准。
2. 输入“@”后从候选列表选择有效成员，确认正文中保留了对应提及文字。
3. 回复某条评论时使用它的“回复”按钮，检查引用对象后输入内容，再发布。
4. 需求评论可使用 Ctrl/⌘ + Enter 发布；需要换行时按普通 Enter。
5. 发布后检查评论已出现在列表；只收到“评论已发布但刷新失败”时，先刷新讨论确认，不要立即重复提交。

注意与常见问题：随意输入同名文字不等于可靠绑定成员，建议始终从候选中选择。提及和回复通知受接收人有效性、项目访问权及去重规则限制；回复与提及同一人不会要求对方处理两份独立业务。历史评论保留作者快照，不因人员改名或删除而随意改写。评论不是授权渠道，不要粘贴密码、机器人密钥或未经许可的个人资料。

## 12 需求状态与工作流

入口：需求列表/详情中的状态选择器；管理员进入[应用设置](/settings/fields)的需求状态、工作流区域。

### 操作步骤

1. 更新状态前确认当前工作已满足约定交接标准，例如开发完成、测试通过或验收完成。
2. 从界面给出的可选目标状态中选择。可选项由当前状态、角色和项目工作流决定。
3. 管理员维护状态的名称、颜色、类别、启停和顺序，再配置允许流转的路径及角色。
4. 配置初始状态和结束状态后保存，使用对应角色核对实际流转入口。

注意与常见问题：显示名称可以调整，稳定状态标识用于保持历史和配置关系；不能只凭颜色判断是否完成。“已完成类别”与“已取消类别”都可能结束工作，但取消不等于成功交付。管理员也应遵守已配置的合法路径，恢复终态需要有明确流转配置。保存冲突时核对最新版本，不要强行覆盖他人修改。状态交接通知针对该需求绑定人员，不代表向整个部门广播。

## 13 迭代规划与完成迁移

入口：[迭代](/iterations)。

### 操作步骤

1. 在“待规划”整理未纳入迭代的需求和缺陷。
2. 管理员创建迭代，填写名称、目标、起止日期、容量和负责人。页面提供日期默认值，可根据真实计划修改。
3. 将工作项的迭代归属改为目标开放迭代，或在迭代中使用“创建工作项”。
4. 准备开始时点击“开始迭代”。迭代无需设置独立负责人，状态变化由项目负责人接收通知。
5. 完成迭代时检查未完成项数量，选择迁回待规划或其他开放迭代，再确认完成。

注意与常见问题：完成操作会一起迁移未完成需求和缺陷并记录历史，不是把全部工作项自动标为完成。已完成/已取消的历史迭代保留已有工作项，但不能作为新增工作项的目标。若发现迭代中没有需求，应检查工作项的真实迭代归属，不能仅凭标题或日期推断已经关联。

## 14 迭代看板、工时与权重统计

入口：迭代详情的工作项列表、看板、权重统计、团队跟踪和分析页签。

### 操作步骤

1. 在列表或看板使用关键词、多选状态和高级筛选，确认显示数量与总数量。
2. 点击“列设置”选择显示字段并调整顺序。首次使用和恢复默认时，“创建时间”位于“标题”后面；已有个人列配置保持不变，创建时间仍可隐藏或移动。在有权限的字段上更新状态、进度或预估/实际工时。
3. 在权重统计中核对需求的职能权重和人员分配；在团队跟踪中查看参与情况。
4. 看风险或完成率时，同时核对未指派、未估算和超出预估的项目，而不是只看单一分数。

注意与常见问题：列表与看板筛选只改变当前看到的工作项，不改写整个迭代的概览和权重总计。多人需求可以分别出现在各参与者名下，但迭代总量按工作项计一次。团队卡片工时是参与工作项的工时，不等于该成员实际投入，也不是自动平均分摊。不要把权重、小时和完成率互相替代。

## 15 缺陷记录、修复与验证

入口：[缺陷](/defects)，或需求/失败测试执行的关联缺陷入口。

### 操作步骤

1. 创建缺陷，填写标题、问题说明、复现步骤、实际结果和预期结果。
2. 区分严重程度与优先级，选择负责人、验证人、职能、关联需求和迭代，补充环境与必要附件。
3. 使用列表或看板追踪；按严重程度、状态、负责人、验证人或“与我相关”缩小范围。
4. 修复后按允许的状态流转交给验证人；验证时记录结果和依据，不通过则按可用路径继续处理。
5. 若缺陷来自测试执行，可从来源链接返回原计划、用例和执行记录进行回归。

注意与常见问题：严重程度描述影响，优先级描述处理先后，两者不一定相同。状态不能任意跳转，可选项以服务端工作流为准。缺陷负责人和验证人是稳定成员绑定，不应仅输入同名文本。支持草稿箱的编辑表单可保存私有草稿，但正式缺陷必须主动创建或保存。外发消息是否送达要到投递记录确认，不能只根据状态已保存判断。

## 16 测试设计：从风险到测试点

入口：[测试设计](/tests?tab=designs)。

### 操作步骤

1. 创建测试设计，填写名称、关联需求、负责人、设计说明和标签。
2. 按正常路径、边界条件、异常场景、权限安全、兼容性或性能拆解测试点。
3. 为每个测试点填写清晰标题和等级，使用上移/下移调整顺序。
4. 点击“关联用例”，搜索并勾选已有用例，确认后保存整个测试设计。

注意与常见问题：测试点描述“要验证什么”，可执行用例描述“如何操作并判断结果”，两者不能只重复标题。新增关联后仍需保存设计。删除测试设计需要管理权限，已关联的用例会保留。这里不是自动生成或运行测试脚本的平台；测试点为空时不会自动补齐覆盖范围。

## 17 用例库、目录与结构化用例

入口：[测试用例](/tests?tab=cases)。

### 操作步骤

1. 选择用例库和目录，按编号、标题或标签搜索，结合优先级、类型、评审状态和负责人筛选。
2. 创建用例，填写标题、前置条件、测试数据和逐步“操作步骤 / 预期结果”。每一步都应能客观判断。
3. 选择所在库/目录、负责人、关联需求、标签及是否启用，完成项目要求的补充字段后保存。
4. 使用“复制”创建相似用例后，核对并修改差异；批量移动前检查选中数量和目标目录。
5. 目录需要调整时使用目录管理操作；仅删除空目录，先处理下级内容和用例归属。

注意与常见问题：用例“启用”和“评审通过”是不同维度，停用不代表删除历史。目录属于具体项目和用例库，不能把其他库的目录直接当作目标。列表全选为当前页，不应误认为所有查询结果。步骤、预期等核心内容不能靠标题替代；修改已评审用例后请查看最新评审状态，不要假设旧结论永远有效。

## 18 AI 生成用例：预览后导入

入口：需求详情的 AI 测试用例区域，或[用例库](/tests?tab=cases)的“AI 生成用例”。

### 操作步骤

1. 先正式保存需求，核对标题、正文与验收标准；从用例库进入时选择生成依据的已保存需求及目标目录。
2. 查看本次发送内容说明，选择覆盖侧重点、生成数量，按需要补充业务背景说明。
3. 确认资料允许发送到外部 AI 服务后勾选授权，再点击“生成用例预览”。调用可能产生服务商费用。
4. 逐条检查标题、前置条件、步骤和预期结果，勾选需要导入的条目。
5. 点击“确认导入所选用例”。导入结果为用例草稿，随后在用例库完善并提交人工评审。

注意与常见问题：生成预览不会自动创建用例；放弃预览不会删除已有用例。需求存在未保存修改、生成依据已更新或预览已过期时，需要先处理并重新生成。相同预览与相同选择的网络重试有重复导入保护，但不要将重复重新生成当作同一次操作。此流程不发送附件、图片、评论和人员资料；仍应检查正文和补充说明是否包含敏感数据。生成数量以页面能力上限为准，目前单次最多 10 条。

## 19 人工评审与 AI 审查

入口：测试用例详情的“评审”页签。

### 操作步骤

1. 先保存用例，再点击“提交评审”，将草稿提交给评审人员。
2. 评审人员检查覆盖、可执行性和预期是否明确；通过则确认通过，退回时填写具体修改意见。
3. 需要 AI 辅助时选择标准审查或逻辑审查，阅读发送范围并明确确认，再开始审查。
4. 阅读风险、建议和待确认项，人工决定是否修改用例；修改后保存并重新核对评审流程。
5. 在评审时间线及变更记录中查看操作人员、时间和意见。

注意与常见问题：人工通过/退回权限属于企业管理员、项目管理员及测试角色，普通业务编辑者不自动拥有评审批准权。AI 审查仅给建议，不自动修改用例，也不自动通过人工评审。AI 读取已保存用例、允许访问的关联需求摘要及相应规则，不包含未保存修改。相同版本的审查结果可能复用；内容变化后应依据新版本重新判断。

## 20 测试计划与测试范围

入口：[测试计划](/tests?tab=plans)。

### 操作步骤

1. 创建测试计划，填写计划名称、范围、迭代、版本、环境、负责人、执行人和起止日期。
2. 搜索并选择已评审通过且启用的用例，跨页选择会保留；核对已选数量。
3. 保存计划后从卡片进入执行列表，确认每个执行项的用例、计划和执行人。
4. 需要调整计划说明、状态或安排时编辑已有计划；需要验证另一组范围时创建新计划。

注意与常见问题：当前产品保留已建计划的用例集合，不在普通编辑中随意重写既有执行范围。用例未通过评审或已停用时不会出现在正常计划候选中，应先处理用例。计划标为完成不等于所有执行项自动通过；计划状态、执行结果和关联缺陷应分别核对。

## 21 测试执行、失败缺陷与回归

入口：[测试执行](/tests?tab=executions)，或测试计划的“查看执行”。

### 操作步骤

1. 按计划、状态、执行人筛选，或使用“我执行的”定位任务。
2. 打开执行项，核对前置条件、测试数据、操作步骤和预期结果，在实际环境逐项验证。
3. 选择未执行、通过、失败、阻塞或跳过，填写实际结果与备注后提交。失败或阻塞必须说明实际情况。
4. 已保存的失败执行可点击“由失败结果生成缺陷”；生成后通过链接追踪，不要手动重复创建同一问题。
5. 回归时提交新的执行结果，在执行历史中保留历次结论，关联缺陷继续可追溯。

注意与常见问题：存在未保存结果时应先保存，再生成缺陷。重复生成入口会复用已有来源关联，不应当作批量造缺陷工具。执行详情展示当前用例内容，历史列表保存执行结论；目前不能把它当成完整不可变的旧版用例内容快照。后续通过不会自动抹掉此前失败记录或删除已生成缺陷。

## 22 质量报告与统计分母

入口：[质量报告](/tests?tab=report)。

### 操作步骤

1. 选择全部计划或一个计划，确认当前统计范围。
2. 查看执行项数量、执行率、已判定通过率及待关注项，再查看结果分布。
3. 进入对应计划或执行记录核查失败与阻塞原因，而不是只看汇总比例。

| 指标 | 当前质量报告口径 |
| --- | --- |
| 计划执行项 | 同一用例在不同计划中分别计数 |
| 已执行 / 执行率 | 通过、失败、阻塞、跳过之和，再除以全部执行项 |
| 已判定通过率 | 通过 ÷（通过 + 失败）；没有可判定项时显示“—” |
| 待关注 | 失败 + 阻塞 |
| 结果分布 | 各状态数量均除以全部执行项 |

注意与常见问题：阻塞、跳过和未执行都不能计作通过。仪表盘采用另一项明确标注的“已执行通过率”，分母含阻塞，因此与此处数值不同不一定是错误。比较两张报表前应先对齐项目、计划范围、时间点和统计分母。

## 23 测试基础设置

入口：[测试基础设置](/tests?tab=settings)。

### 操作步骤

1. 企业管理员或项目管理员进入“用例模板”，配置补充字段的启用、必填、默认值和列表展示。
2. 在测试结果选项中决定是否允许新结果选择“阻塞”。

## 24 站内通知与 3 秒更新

通知中心可直接切换“分配与交接”“提及与回复”“需求与状态变更”“其他动态”。分类数字是所选项目范围的未读数，顶部仍为账号可见项目的未读总数。分类和条件在服务器分页前执行，可用上一页/下一页查看历史消息；阅读通知不会完成对应业务交接。

入口：顶部通知角标；[通知中心](/notifications)的“站内通知”。

### 操作步骤

1. 查看分配、状态变化、提及、回复或安全等消息，按已读状态、事件和项目筛选。
2. 点击消息打开对应工作项；单条可设为已读/未读，也可使用“全部标为已读”。
3. 留在可见页面时，通知列表和顶部未读角标通常每 3 秒检查更新；返回窗口、切回可见页面及本页产生消息时也会刷新。
4. 怀疑显示滞后时，使用通知页“刷新”，再核对账号、项目筛选和网络状态。

注意与常见问题：3 秒是正常可见页面的检查间隔，不是必达时限。隐藏页、网络异常、已有请求进行中、账号或项目正在切换等情况下会延后。通知按账号隔离；拿到工作项链接不等于有访问权。标为已读不会修复工作项、完成测试或改变外发投递状态。

## 25 企业微信机器人与外发记录

入口：[个人设置](/profile)的“企微通知”；管理员可从成员列表的“机器人”入口配置；通知中心另有受限的“外发队列”。

### 操作步骤

1. 在获授权的企业微信群准备群机器人地址，粘贴到“机器人 Webhook 地址”。当前支持企业微信官方 HTTPS 群机器人地址。
2. 选择是否启用，点击“保存机器人设置”。已有地址只显示掩码，留空可保留，填写新值才替换。
3. 等待该成员的分配、状态交接、提及等符合投递条件的新通知，查看机器人设置下的“最近投递记录”；保存配置不会主动发送测试消息。
4. 不再使用时关闭通知或移除地址；这不会关闭站内通知。
5. 管理员诊断系统外发时查看外发队列的渠道、状态、失败原因和重试入口，同时区分个人机器人投递记录。

### 批量配置机器人

在成员管理中勾选目标后选择“配置机器人”。可以只启用已有地址、只停用已有地址，或为选中成员统一设置新地址。统一设置时可选择保留原启用状态、全部启用或全部停用，提交前需确认共用同一群机器人的信息可见范围。启用已有地址时，若任一目标没有可用配置，整批失败，不会只修改部分成员。新地址仅在输入期间保留，不写入浏览器缓存；保存不主动发送测试消息。

注意与常见问题：当前已有个人群机器人投递实现，不应理解为只有企业应用模拟演示。但是否真实发送由部署模式决定：“模拟发送”不是消息已到达群聊，“待发送”也不等于成功。启用不会自动补发全部历史；自动化规则通知同样进入已启用的个人机器人队列。长通知分段完整发送，界面显示已确认段数；每段带分类、通知编号、时间与详情链接。只有全部分段确认后才标记真实投递成功。账号撤权、停用或配置已变化时，旧待发项可能被跳过。外部网络重试存在重复送达可能，不能承诺端到端恰好一次。机器人会把该成员相关信息发送到整个绑定群，配置前确认群成员有权看到这些内容。地址密钥不得放进需求、邮件或截图。

## 26 全局搜索与导出范围

入口：顶部搜索；[全局搜索](/search)；需求列表的导出按钮。

### 操作步骤

1. 用 Ctrl/⌘ + K 聚焦顶部搜索，输入编号或较短关键词，再进入结果。需求和缺陷也支持按负责人、开发人员姓名或其当前直属部门名称搜索；需求覆盖多位负责人、职能人员及启用的人员字段。需求池、缺陷列表同样支持这些关键词。
2. 在全局搜索中选择项目、需求、迭代、缺陷、测试用例或测试计划等类型，按可访问项目过滤。

注意与常见问题：导出为 CSV 列表，不是包含所有附件和全部项目数据的备份。搜索页的导出只包含结果中的需求，不会顺带导出其他类型。需求编号组件支持双击复制摘要，也可在编号聚焦时使用 Ctrl/⌘ + C；复制的摘要和链接仍须按业务保密要求分享。

## 29 月度工作量与团队趋势

## 30 企业概览与部门管理

### 操作步骤

1. 在企业概览查看成员、部门、权限组和待审批数量，按自己的授权进入管理分区。
2. 创建部门，填写名称、代码和上级部门；按组织层级组织部门树并调整顺序。
3. 人员可以属于多个部门，但应选定有效主部门，用于默认归类及部分统计。
4. 调整或移除部门前，先核对下级部门、成员和人员字段引用；有使用关系时优先迁移或停用，而不是直接删除。

注意与常见问题：部门以稳定标识关联，不是凭显示名称推断。新部门不会自动赋予成员项目权限，也不会自动给成员绑定需求职能。成员列表按部门树顺序归类，同部门按姓名排序；无有效主部门时取所属部门树序首项，未分配部门放后。部门维护需要“管理部门”授权；不能用项目管理员身份替代企业授权。

## 31 添加成员、账号状态与删除历史

入口：[成员管理](/organization/members)。

### 操作步骤

1. 点击“添加成员”，填写姓名、登录邮箱、工号，选择部门和主部门。
2. 为账号分配所需项目及角色，按实际入职流程决定是否激活；初始密码按组织安全策略处理。
3. 点击保存后核对列表状态。新增空表单可直接取消；已修改的表单会要求选择继续编辑或放弃修改，取消不会提交表单。
4. 编辑已有成员时，密码留空表示不修改。配置好系统初始密码时，新建可按界面说明留空使用该流程并要求首次改密。
5. 要临时停止业务可使用状态切换；要撤销账号激活状态或全部企业成员关系，应选择对应操作并阅读确认说明。

### 快速激活与批量动作

1. 点击未激活成员的状态按钮可逐个快速激活；激活同时解除业务禁用，不自动授予项目或管理员权限，也不重置已有密码。
2. 勾选行复选框，或通过表头选择当前页；“全选筛选结果”明确选择全部匹配成员，单批最多 200 人。翻页保留选择，修改筛选或重新加载后应重新核对目标。
3. 从批量工具栏选择激活、停用、配置机器人或删除成员，核对确认窗口中的人数和名单后提交。
4. 批量停用会关闭登录并使现有会话失效；删除会撤销成员访问关系并保留业务历史，两者不能用于自己或任何企业管理员。
5. 整批操作在一个事务中校验并保存，任一目标失效、越权或配置不合法都会整体回滚。网络中断导致结果不明时，先刷新核对状态，勿连续重复提交。

| 状态或操作 | 实际含义 |
| --- | --- |
| 已启用 | 已激活且未禁用业务，仍受项目授权限制 |
| 已禁用 | 可以登录，但不能访问或操作业务数据 |
| 未激活 / 已停用 | 不能正常进入业务登录流程，需要管理员处理 |
| 删除成员 | 撤销组织、部门、项目和权限组访问，终止会话，保留业务与审计历史 |

注意与常见问题：普通成员未选择项目就无法访问项目内需求和缺陷。管理员权限调整受更高等级安全授权限制；只有企业管理员可删除成员，且不能删除自己。删除没有普通撤销入口，不能当作禁用的快捷替代。被删除成员的需求、缺陷、评论和审计历史保留，不应再创建同名账号来伪装为原历史身份。

## 32 用户组权限与代访问

入口：[用户组权限](/organization/groups)；成员管理的“代访问账号”。

### 操作步骤

1. 企业管理员创建职责明确的用户组，例如“目录维护”，选择可委派的成员管理、部门、邀请、导入导出或统计权限。
2. 加入确实需要这些能力的成员，保存后使用对应账号核对入口。
3. 职责变化时移除组成员或撤回权限，同时检查其独立项目角色是否也需调整。
4. 需要排查某成员视角时，有权的企业管理员可发起代访问，按页面要求确认；结束后使用“返回管理员”。

注意与常见问题：用户组赋予企业管理能力，不改变项目业务角色。权限组管理和管理员权限调整不能通过普通可委派权限层层扩权。代访问不是知道对方密码，也不等于目标账号获得管理员能力；必须始终确认当前身份标记。代访问期间某些安全配置、私有草稿和外部接入操作会被限制，不能用于绕过授权。

## 33 邀请链接、加入申请与 CSV 导入

入口：[邀请链接](/organization/invitations)、[加入申请](/organization/applications)、[成员管理](/organization/members)的导入/导出。

### 邀请与审批

1. 有权限的管理员创建申请链接，限定允许部门、申请角色、有效期和使用次数。
2. 申请人打开链接填写姓名、部门和申请角色并提交；此时还不是已获批准的登录账号。
3. 审批人核对信息，确定登录邮箱、凭据处理与项目角色后批准；不符合条件则填写原因拒绝。
4. 不再需要的链接及时撤销。批准激活后，申请人再按登录和首次改密流程使用产品。

### 批量导入

1. 下载当前 CSV 模板，按模板填写 UTF-8 CSV，部门用部门代码、项目用项目代号、角色用角色标识。
2. 上传文件或粘贴内容，点击“预览并校验”，逐行处理重复邮箱、无效代码及角色等错误。
3. 核对预览并勾选确认后导入。当前上限为 500 行、约 1 MiB；不接受密码列。
4. 导入仅新建未激活的普通成员，不覆盖已有账号。导入后审核名单、配置必要凭据和项目访问，再逐个或批量激活。

注意与常见问题：邀请链接是申请入口，不是免审批登录链接。CSV 中即使有兼容导出的 active 列，也不能借此自动激活；导入成功不代表成员已能登录。导出目录不含登录凭据，但仍包含个人资料，应限制分发范围。导入、导出、邀请和审批分别授权，不是任一目录管理者都能操作全部流程。

## 34 应用字段配置

入口：[应用设置](/settings/fields)的工作项字段区域。

### 操作步骤

1. 选择需要配置的对象，例如需求、缺陷或测试用例，先区分系统字段与自定义字段。
2. 创建字段时填写稳定标识、名称、类型、选项、默认值和排序，再设置启用、必填、可搜索、可筛选及列表展示。
3. 人员字段需要限定部门时，选择真实部门并核对候选成员；保存后在业务表单检查。
4. 使用“一键补齐默认配置”只补缺失预置项；已有配置不会被批量覆盖。
5. 删除自定义字段前检查保存视图、列表和团队使用情况，再确认删除。

注意与常见问题：字段标识和类型创建后不能直接修改，设计前应确认含义。人员候选是部门限制与有效项目成员的交集，不是全公司任意姓名。删除会移除表单、列表和筛选配置中的字段，但保留历史值和审计，不删除业务对象；重启和默认补齐不会自动恢复已删除字段。引用它的保存视图会提示失效，需主动修复。配置仅作用于当前项目，需要企业或项目管理员权限。

## 35 自动化规则与安全演练

入口：[应用设置](/settings/fields)的“自动化规则”。

### 操作步骤

1. 创建规则，填写名称，按需要限制需求状态的来源和目标。
2. 选择需求上的处理人、负责人、职能绑定人员或指定有效成员作为接收人。
3. 先点击“演练”，检查匹配样例和范围；演练不会发通知，也不会猜测工作项的历史来源状态。
4. 保存规则并明确启用。新规则默认关闭，也可在表单显式选择保存后立即启用。
5. 不再需要时关闭或删除；删除规则保留已执行记录用于追溯。

注意与常见问题：当前触发器仅是需求状态变化，动作固定为站内通知；不是定时任务、自动改字段、脚本执行或通用 Webhook 平台。规则中的“前端工程师”等表示该需求绑定的职能成员，不是向所有同角色成员广播。真实执行会再次核对接收人的当前权限，没有有效接收人则记录跳过。自动化站内通知会同步进入已启用的个人企业微信机器人队列；未配置或未启用时仍只保留站内消息，邮件尚未接入。

## 36 AI 服务配置与数据边界

入口：[AI 服务设置](/settings/ai)；业务入口为需求标题、用例生成及用例审查。

### 操作步骤

1. 企业管理员按组织批准的方案配置模型及 API 密钥，确认启用开关后保存。
2. 已配置密钥不回显明文；更新时按页面提示填写新密钥，留空保留旧配置。
3. 成员在每次业务调用前阅读发送范围并明确确认，先查看生成或审查结果再决定采纳。
4. 不再允许调用时停用服务，并检查外部服务商处的密钥状态和费用管理。

注意与常见问题：保存配置不验证密钥，不会主动发起模型调用；“已配置”不等于外部服务一定可用。标题总结、用例生成、用例审查发送的字段范围不同，以对应入口说明为准；不可笼统承诺所有业务内容都不含敏感信息。不要发送未经授权的个人资料、客户密钥和商业机密。产品内 AI 辅助不等于外部客户端已获项目访问权；外部客户端/API 接入另见[API 接入指南](/help/api)。

## 37 个人资料、语言、主题与本地缓存

入口：[个人设置](/profile)、顶部语言与外观入口、各选择器的近期记录。

### 操作步骤

1. 在基本资料维护页面允许修改的联系资料、职位、简介和头像颜色，点击保存。
2. 在偏好设置选择简体中文或英文及时间显示时区；业务文本保持原文。
3. 按自己的习惯调整界面外观、桌面侧栏和抽屉宽度，人员选择器可使用近期选择并清除近期记录。
4. 浏览器异常时先保存正式内容或导出未同步草稿，再考虑清理站点数据，最后重新登录并确认当前项目。

注意与常见问题：个人资料、语言等账号设置与部分本机界面偏好不是同一种存储。侧栏、项目收藏、抽屉宽度、近期人员及上次邮箱等可能仅在当前浏览器保留；本机偏好不代表权限。私有草稿的本机副本也可能受清理影响。“邮件通知”目前仅保存偏好，邮件投递尚未接入，关闭或开启不会改变站内通知。清缓存不能撤回服务器已保存业务，也不是备份或删除账号的方法。

### 页面身份水印

登录后的工作区默认显示淡色平铺水印，包含账户名称、时间和 IP。水印覆盖页面、抽屉与弹窗，但不阻挡点击、搜索或输入；登录页与公开门户不展示账户水印。

时间每秒更新并定期与服务器同步，按账户时区显示。本机访问通常显示 `127.0.0.1` 或 `::1`；经过反向代理时显示代理的连接地址，不一定是终端公网 IP。网络失败时 IP 显示“暂不可用”，恢复后自动重试。

截图会包含水印信息，请遵循保密要求。水印是可视溯源提示，不是不可移除的防泄漏措施，也不会自动写入导出的 PDF/JSON/Markdown 或原生 Mac 窗口。

## 38 变更历史与协作冲突

入口：工作项详情中的活动/变更记录；管理员的[变更历史](/audit)。

### 操作步骤

1. 先从工作项自身记录确认谁在何时修改了内容、状态或执行结果。
2. 有项目管理权限时进入变更历史，按对象、动作、操作人和时间范围筛选，加载更多历史。
3. 查看前后值差异；需要业务背景时打开关联工作项，不要仅凭一个字段变化推断原因。
4. 编辑出现“版本已变化”时保留当前输入，先读取最新内容再人工合并或重做更改。

注意与常见问题：历史是追溯信息，不提供任意“撤销整个版本”的保证。长差异可能截断或只显示摘要，凭据等敏感内容不会作为可用密钥展示。历史用户名称或已失效链接可以继续存在；这不代表历史成员仍有访问权限。请求成功但后续刷新失败时，应先核实正式记录和历史，避免重复提交。

## 39 常用快捷操作

入口：对应搜索框、编号、富文本编辑器和弹窗中。

| 操作 | 作用范围与结果 |
| --- | --- |
| Ctrl/⌘ + K | 聚焦顶部全局搜索 |
| 双击需求编号 | 复制该需求的摘要信息；单击用于打开详情 |
| 编号聚焦后 Ctrl/⌘ + C | 复制需求摘要 |
| 需求评论中 Ctrl/⌘ + Enter | 发布评论 |
| @ 候选中的上下方向键、Enter | 移动并选中提及成员 |
| Esc | 关闭当前候选或最上层可关闭界面；富文本全屏先退出全屏 |

常见问题：按键没有反应可能是焦点在浏览器、输入法候选或其他弹层中。先关闭顶层菜单，再回到目标编辑区；不要连续按回车尝试关闭弹窗，以免触发表单提交。

## 40 常见故障的处理顺序

入口：问题所在页面的错误提示、刷新/重试按钮，以及本手册相关章节。

### 操作步骤

1. 记录当前账号、项目名、页面、工作项编号、操作时间和错误原文，不记录密码或密钥。
2. 确认是否有未保存输入，先保存草稿或下载必要副本，再进行导航或刷新。
3. 从下表做最小范围检查；仍未解决时，把脱敏信息交给管理员或维护人员。

| 现象 | 优先检查 |
| --- | --- |
| 没有数据或搜索不到 | 当前项目、筛选、分页、归档状态和访问权限 |
| 按钮灰色或不能编辑 | 只读角色、账号禁用、首次改密、代访问限制、保存/上传是否仍在进行 |
| 添加成员“取消”未立即关窗 | 查看是否已修改表单并出现放弃确认；未修改应直接关闭，确认时选“放弃修改” |
| 保存被拒绝 | 必填字段、日期、人员失效、非法状态路径或并发版本冲突 |
| 保存成功但列表没刷新 | 先刷新对应列表/讨论核实，不要重复创建 |
| AI 无法生成 | 企业是否启用、授权勾选、依据是否正式保存、预览是否过期；外部服务问题联系管理员 |
| 通知角标慢或企微没消息 | 页面可见性、网络、站内事件、机器人配置、部署模式和实际投递状态 |
| 草稿只有本机状态 | 网络和私有草稿同步提示；先导出本机副本再处理浏览器数据 |
| 提示账号或项目已变化 | 停止旧页写入，确认其他标签的身份变化，保存必要副本后重新进入 |
| 暂时无法打开工作空间 | 使用重新连接；服务故障不是必须反复登录或清库的理由 |

注意与常见问题：不要通过更改网址中的项目参数、复制别人的链接或清缓存尝试绕过权限。不要把生产数据重建、批量删除、重置所有密码当作一般排障步骤。若不确定某次写入是否成功，先核实详情、历史或导入结果，再决定是否重试。

## 个人需求模板：产品经理快速填写

入口：新建需求或打开已有需求的“完整编辑”，在正文区域上方找到“我的需求模板”。产品角色及管理员可管理自己的模板，其他成员和其他管理员看不到你的模板。

1. 点击“新建模板”，填写名称、Markdown 描述、验收标准和备注，也可设置各职能难度、工程师、负责人及测试负责人，再保存。支持代码块、标题和列表等现有 Markdown 解析能力。
2. 选择模板后点击“填入空白”，只填尚未填写的内容，保留已有描述、标题及人员关系。
3. 若需替换已有内容，选择“替换内容”并确认；模板中为空的字段不清空需求已有字段。已配置的难度和人员也会替换；模板不会修改标题、迭代、状态、优先级或附件。
4. 填入后仍是当前编辑草稿，请检查后保存需求。保存或编辑模板本身不会发送业务通知，也不会修改以前使用过该模板的需求。
5. “编辑模板”和“删除模板”仅影响自己的模板；多窗口修改冲突时会提示刷新，不会静默覆盖另一窗口的新版本。

模板每人最多 100 个，按账号保存在服务器，可用于新建、子需求及已有需求完整编辑。Markdown 内容不会将文本中的人名自动绑定为负责人或批量 @ 他人。

## 41 备份、运维与产品能力边界

入口：由获授权维护人员使用[维护手册](maintenance-zh.md)和[内部接口说明](internal-api-reference.md)；普通用户优先使用产品内保存、导出和恢复入口。

### 操作步骤

1. 普通成员先确认业务已正式保存；重要未同步草稿可导出，业务清单可按需导出 CSV。
2. 管理员发起批量导入、删除、权限重组或版本升级前，应与维护人员确认影响范围、最新备份和回退方案。
3. 运维备份应覆盖数据库、附件及加密配置所需的原始密钥，并核对部署配置；仅复制数据库不足以保证机器人和 AI 密钥可恢复。
4. 恢复前先在隔离副本验证数据和权限，确认目标环境后再按批准步骤切换；恢复后检查登录、业务数据、附件、通知及安全配置。

注意与常见问题：普通导出、草稿 JSON 和页面截图都不是完整备份。丢失原加密密钥时，不能通过随意生成新密钥解开已有配置。帮助页面不会自动备份、部署、清理成员或重置密码，也不保证外部服务可用。当前测试执行以人工记录为主，不提供通用自动化脚本运行平台；路线图不是自动排程引擎，审计不是任意版本恢复器。任何有删除或覆盖风险的运维操作，都必须有明确授权、目标复核和可验证的恢复方案。


### 个人模板：难度和人员配置（2026-09-08）

个人模板现支持保存前端、后端、算法、UI、产品难度及各职能工程师，以及负责人（产品角色）和测试负责人（测试角色，对应需求的测试人员字段）。旧模板保持兼容。模板不保存迭代、附件或工作流状态，也不会触发通知。

接口新增可选字段 `roleWeights`、`ownerUserIds`、`testerUserIds`。难度范围为 0–1000000，留空表示未评估；每组人员最多 50 人。保存时校验当前项目有效成员、职能和测试部门限制。

“填入空白”保留已填写字段；“替换内容”在确认后替换模板中已配置的文本、难度及人员，仍不改变标题、迭代。跨项目或人员变更导致候选不可用时，确认后跳过，不自动替换成同名人员。填写结果仍需保存需求才生效。创建页与详情页选择迭代时，进行中的迭代优先展示并标注“当前进行中”。
